# TrueWebsiteCloner V1.1 Roadmap

V1.1 extends the V1.0 capture model while keeping sensitive authentication material disabled by default and preserving deterministic gates.

## Gate 1.1 — WebSocket capture

Status: implementation branch.

Capture same-origin WebSocket lifecycle and bounded frame payloads through Chrome DevTools Protocol. Maximum stored frame payload: 64 KiB. Handshake headers, cookies and Authorization remain excluded.

## Gate 1.2 — XHR / Fetch request payloads

Planned.

Capture bounded request payloads for same-origin XHR/Fetch requests with explicit content-type rules, deterministic byte limits and metadata-only fallback for unsupported or oversized payloads. Credentials, cookies and authorization material remain excluded from the default capture path.

## Gate 1.3 — Safe HTTP headers

Planned.

Add allow-listed request/response header capture with mandatory redaction/exclusion for sensitive fields such as `Authorization`, `Proxy-Authorization`, `Cookie` and `Set-Cookie`. The gate must verify that unapproved headers cannot bypass the Core sanitizer.

## Gate 1.4 — Deterministic API replay fixtures

Planned.

Use captured same-origin request/response fixtures to improve local replay matching by method, normalized URL and bounded request payload. Authentication replay is not enabled by default. Replay must remain local and deterministic.

## V1.1 completion rule

V1.1 is not releasable until every new gate is green together with the existing V1.0 regression/release-candidate sweep.
